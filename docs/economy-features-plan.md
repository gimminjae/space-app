# space 경제 사이트 — 5개 기능 구현 계획서

- 작성일: 2026-10-16
- 문서 상태: 구현 범위와 설계를 정리한 검토용 계획서
- 대상 서비스: [space.service.io.kr](https://space.service.io.kr)
- 저장소: [gimminjae/space-app](https://github.com/gimminjae/space-app)
- 설계 기준: 현재 저장소 `07c3e3f`의 코드·마이그레이션·운영 문서
- 기술 기반: Next.js App Router · TypeScript · Supabase · AWS S3 · Netlify

## 1. 목표와 구현 범위

space를 **경제 글을 읽고, 이해하고, 자신의 자료로 정리하며, 경제 변화와 새 글을 다시 확인하는 서비스**로 확장한다. 기존 개인 공간·글 작성·마이페이지에 다음 5개 기능을 연결한다.

| 기능 | 사용자가 할 수 있는 일 | 핵심 목표 |
| --- | --- | --- |
| 북마크·개인 메모 | 글 저장, 폴더 분류, 비공개 메모 작성 | 개인 경제 공부 자료 축적 |
| 경제 용어 사전 | 용어 검색, 본문에서 뜻 확인, 관련 글 탐색 | 이해도 향상과 검색 유입 |
| 공간 팔로우·관심 주제 피드 | 공간·주제 구독, 해당 공개 글 모아보기 | 회원 간 연결과 재방문 |
| 주요 경제지표 대시보드 | 지표 수치·추이·해설·출처 확인 | 경제 상황 파악 |
| 경제 일정 캘린더 | 주요 발표 일정 확인, 관심 일정 저장 | 발표 전후의 지속적인 방문 |

모든 기능은 한국어와 영어, 데스크톱과 모바일을 함께 지원한다. 회원이 작성한 글·메모·공간 이름은 원문을 유지한다.

### 현재 기반과 선행 조건

현재 코드에는 회원 로그인, 회원당 하나의 개인 공간, 공개·비공개 글, Markdown 편집기, 카테고리·태그, 마이페이지, 언어별 URL, 사이트맵·RSS가 있다. 신규 기능은 이를 확장한다.

현재 카테고리·태그는 **회원 공간별 분류**다. 따라서 사이트 전체에서 구독할 수 있는 **공통 주제**를 별도로 도입한다. 기존 카테고리와 태그를 일괄 교체하지 않는다.

운영 문서상 일반 회원가입·인증 메일은 SMTP 및 Redirect URL 설정 완료 전까지 비활성 상태다. 기존 인증 계정으로 개발·검증할 수 있지만, 신규 방문자에게 개인화 기능을 정식 개방하려면 인증 메일 연결을 먼저 마무리해야 한다. 이 문서 작성 과정에서는 운영 설정을 변경하지 않았다.

## 2. 1차 출시의 기본 결정

| 항목 | 적용할 기준 |
| --- | --- |
| 로그인 없이 사용 | 공개 글·용어 사전·공통 주제·경제지표·경제 일정 열람 |
| 로그인 후 사용 | 북마크, 메모, 팔로우, 개인 피드, 관심 지표·일정 저장 |
| 개인 공간이 없는 회원 | 읽기·저장·구독 기능 사용 가능. 글 작성 시에만 공간 생성 필요 |
| 개인 정보 공개 범위 | 메모·폴더·저장 목록·구독 목록·관심 설정은 본인만 열람 |
| 피드 방식 | 구독 조건에 맞는 공개 글을 최신 게시순으로 조회 |
| 데이터 범위 | 한국·미국의 핵심 거시경제지표 및 발표 일정부터 제공 |
| 시간 표시 | 기본 Asia/Seoul. 일정 화면에 한국 시간 기준임을 명시 |
| 용어·주제 운영 | 버전 관리하는 데이터 파일과 서버 전용 등록 스크립트로 운영 |
| 알림 범위 | 사이트 내 목록과 저장 기능. 이메일·브라우저 푸시 발송은 후속 범위 |
| 자동화 범위 | 공식 자료 수집·정규화·갱신. AI 자동 요약·번역·투자 추천은 후속 범위 |

다음 기능은 1차 출시에 포함하지 않는다: 주식 매매·계좌 연동, 실시간 시세, 유료 컨센서스 데이터, 댓글·쪽지, 공개 메모, 외부 사이트 전체 스크랩, 범용 운영자 CMS. 5개 핵심 기능은 모두 1차 구현 범위에 포함한다.

## 3. 화면과 탐색 구조

상단에는 글 탐색, 경제 용어, 경제지표, 경제 일정을 배치한다. 로그인 시 내 피드와 마이페이지로 접근할 수 있다. 모바일에서는 메뉴를 접고 핵심 행동을 한 열로 배치한다.

| 화면 | 한국어 URL | 주요 내용 |
| --- | --- | --- |
| 마이페이지 | `/mypage` | 기존 계정·글 관리 + 저장 글 수, 구독 수, 관심 일정 요약 |
| 저장한 글 | `/mypage/bookmarks` | 폴더, 검색, 북마크, 개인 메모 |
| 구독 관리 | `/mypage/following` | 구독한 공간·주제, 구독 해제 |
| 내 피드 | `/following` | 공간·주제 구독에 맞는 공개 글 |
| 공통 주제 탐색 | `/topics`, `/topics/[slug]` | 주제 설명, 공개 글, 주제 구독 |
| 용어 사전 | `/glossary`, `/glossary/[slug]` | 검색·분류, 용어 설명, 관련 용어·글 |
| 경제지표 | `/indicators`, `/indicators/[slug]` | 요약 카드, 차트·표, 설명, 출처 |
| 경제 일정 | `/calendar`, `/calendar/[id]` | 월간·목록 보기, 일정 상세, 저장 |
| 내 관심 일정 | `/mypage/events` | 저장한 일정, 예정·지난 일정 구분 |

영어는 기존 규칙대로 같은 주소 앞에 `/en`을 붙인다. API는 `/api/...`를 공통 사용한다. 언어 전환 시 폴더·기간·국가·주제 필터를 유지한다.

```text
공개 글 ── 저장·메모 ── 내 자료함
   │
   ├── 용어 설명 ── 용어 상세 ── 관련 글
   ├── 공간·주제 구독 ── 내 피드
   └── 관련 지표·일정 ── 추이 확인·일정 저장

마이페이지 ── 내 자료함 / 구독 관리 / 관심 지표 / 관심 일정
```

## 4. 기능별 상세 계획

### 4.1 북마크·개인 메모

**사용 흐름**

1. 글 상세에서 ‘저장’을 누른다. 비로그인 상태라면 로그인 후 원래 글로 돌아온다.
2. ‘분류 없음’ 또는 직접 만든 폴더에 저장한다.
3. 저장한 글에 개인 메모를 작성한다.
4. 마이페이지의 저장한 글 목록에서 검색·폴더 이동·메모 수정·삭제를 수행한다.

**세부 동작**

- 글당 북마크 1개, 폴더는 1개 지정한다. 같은 글의 반복 저장은 중복 행을 만들지 않는다.
- 폴더 이름은 1~40자, 회원당 최대 50개, 같은 회원 안에서는 중복 이름을 막는다.
- 메모는 최대 5,000자의 일반 텍스트로 시작한다. 메모 저장 버튼과 저장 상태를 제공하고, 미저장 변경을 남긴 채 이동하면 확인한다.
- 목록은 한 번에 20개를 제공한다. 제목·메모 검색, 폴더 필터, 저장순·메모 수정순 정렬을 지원한다.
- 폴더를 지우면 북마크는 ‘분류 없음’으로 이동한다. 북마크를 지울 때 메모도 삭제됨을 안내한다.
- 읽을 권한이 있는 글만 새로 저장할 수 있다. 자신의 비공개 글은 저장할 수 있다.
- 글이 비공개·삭제 상태로 바뀌면 타인의 저장 목록에서 원문 제목·요약·이미지·링크를 숨기고 ‘현재 볼 수 없는 글’로 표시한다. 본인이 직접 쓴 메모는 유지한다.
- 원문을 별도 복제하거나 제목 스냅샷을 저장하지 않는다. 원문 영구 삭제 시 연결을 비우고 메모를 남길 수 있도록 설계한다.

**완료 기준**

- 회원 A의 폴더·메모를 회원 B와 비로그인 사용자가 API 직접 호출로도 읽거나 바꿀 수 없다.
- 다른 회원의 폴더 ID로 북마크를 이동할 수 없다.
- 글 공개 상태 변경이 저장 목록에도 다음 요청부터 반영된다.
- 동시에 메모를 수정하면 버전 충돌을 알려 주며, 마지막 저장이 다른 수정을 조용히 덮어쓰지 않는다.

### 4.2 경제 용어 사전

**사용 흐름**

1. 사전에서 한국어·영어·약어로 용어를 검색한다.
2. 용어별 페이지에서 한 줄 정의, 쉬운 설명, 예시, 관련 용어·글을 확인한다.
3. 글 본문의 용어를 누르면 짧은 설명이 열리고, 필요하면 상세 페이지로 이동한다.

**세부 동작**

- 초기 30개 용어를 한국어·영어로 직접 작성하고 검수한다. 기준금리, 인플레이션, 디플레이션, CPI, GDP, 실업률, 환율, 채권, 국채금리, 기준금리와 시장금리의 차이 등을 포함한다.
- 두 언어는 동일한 용어 ID와 안정적인 영문 slug를 공유한다. 언어별 제목·설명·예시·SEO 설명을 관리한다.
- 용어 데이터에는 이름, 약어·별칭, 요약, 본문, 예시, 주제, 출처 URL, 검토일, 공개 상태를 둔다.
- 설명은 자체 문장과 예시로 작성한다. [한국은행 경제금융용어 자료](https://www.bok.or.kr/portal/bbs/B0000249/view.do?menuNo=200765&nttId=235017) 등 공식 자료는 사실 확인과 출처 연결에 활용한다.
- 본문 연결은 Markdown을 HTML로 변환하기 전 텍스트 노드를 분석한다. 기존 링크, 코드, 이미지 대체 텍스트, 제목, 이미 연결된 용어는 제외한다.
- 한 글에서 같은 용어는 처음 1회만 연결하고 최대 10개로 제한한다. 긴 별칭을 우선하며 `CPI`가 다른 영단어 일부와 잘못 일치하지 않도록 한다.
- 데스크톱은 클릭·키보드 초점으로 설명을 열고, 모바일은 탭으로 열리는 설명 창을 제공한다. 마우스 올리기에만 의존하지 않는다.
- 관련 글은 연결된 용어와 공통 주제를 기준으로 최대 6개를 보여 주고, 공개·삭제 조건을 매번 확인한다.
- 검수 전 용어와 비어 있는 번역 페이지는 공개하지 않는다. 한국어 설명만 있는 경우 영어 화면에서 이를 명시하고 원문으로 연결한다.

**운영 방식과 완료 기준**

- 1차에는 `content/glossary/`의 검수된 데이터 파일을 Git으로 관리하고, 서버 전용 동기화 스크립트로 등록한다. 일반 회원은 용어를 생성·수정할 수 없다.
- 현재 `/admin`은 회원 자신의 글을 관리하는 화면이다. 이 화면에 사이트 공통 데이터 수정 권한을 부여하지 않으며, 공통 자료 운영은 저장소 접근 권한이 있는 운영자의 등록 절차로 분리한다.
- 단순 글 편집이 용어 콘텐츠나 설명 링크를 손상시키지 않는다.
- 공개 용어는 직접 URL 접근, 서버 렌더링, canonical, 언어별 대체 링크, 사이트맵을 지원한다.
- 비공개 글의 존재·제목이 관련 글이나 용어 사용 건수에 노출되지 않는다.

### 4.3 공간 팔로우·관심 주제 피드

**사용 흐름**

1. 개인 공간 또는 글에서 ‘공간 구독’을 누른다.
2. 주제 화면에서 관심 주제를 선택한다.
3. ‘내 피드’에서 구독한 공간 또는 주제에 해당하는 글을 확인한다.
4. 구독 관리에서 공간·주제를 해제한다.

**공통 주제 도입**

- 초기 주제는 경제 기초, 거시경제, 금리·통화정책, 주식·기업, 부동산, 환율·국제경제, 물가·생활경제, 재정·정책의 8개다.
- 글 작성자는 기존 카테고리·태그와 별도로 공통 주제를 최대 3개 선택한다. 주제는 선택 항목이며, 미지정 글도 공간 구독 피드에 나타난다.
- 기존 글은 기본 카테고리의 이름·slug가 모두 일치하는 경우만 변환 후보로 제시한다. 사용자 지정 분류는 자동 확정하지 않고 작성자가 선택하게 한다.
- 공통 주제는 사이트가 관리한다. 회원이 자기 공간의 카테고리 이름을 바꿔도 사이트 전체 주제에는 영향을 주지 않는다.

**피드 규칙**

- 조건은 ‘구독한 공간 **또는** 구독한 주제’다. 두 조건에 모두 맞는 글도 한 번만 표시한다.
- `status='public'`, `deleted_at IS NULL`인 글만 포함한다. 작성자 본인의 비공개 글도 이 피드에는 포함하지 않는다.
- 게시일과 글 ID를 묶은 안정적인 커서로 최신순 20개씩 제공한다. 글 수정만으로 맨 위에 다시 올리지 않는다.
- 글마다 ‘구독한 공간’, ‘관심 주제: 금리’처럼 노출 이유를 보여 준다.
- 구독 전 작성된 공개 글도 포함한다. 구독이 없으면 공개 주제·공간 탐색을 안내한다.
- 구독 관계는 본인만 열람·변경한다. 1차에는 구독자 명단과 공개 구독자 수를 제공하지 않는다.
- 자기 공간 구독은 막고, 같은 대상에 대한 반복 구독·해제는 안전하게 처리한다.

**완료 기준**

- 공간 구독·주제 구독·중복 일치·구독 해제의 결과가 정확하다.
- 페이지를 더 불러올 때 동일 글이 중복되지 않는다.
- 원문 비공개 전환·삭제 후 피드, 주제 페이지, 관련 글에서 즉시 제외된다.
- 인증된 회원 DB 조회라도 공개 조건을 생략하지 않는다.

### 4.4 주요 경제지표 대시보드

**사용 흐름**

1. 대시보드에서 한국·미국의 핵심 지표를 확인한다.
2. 지표를 선택해 기간별 차트, 원자료 표, 지표의 의미를 확인한다.
3. 관련 용어와 해설 글로 이동하거나 관심 지표로 저장한다.

**초기 데이터 범위**

| 지표 | 우선 데이터 제공 경로 | 기본 표시 |
| --- | --- | --- |
| 한국 기준금리 | 한국은행 ECOS | 금리 %, 직전 값 대비 %p |
| 원/달러 환율 | 한국은행 ECOS | 원/달러, 직전 관측 대비 원·% |
| 한국 소비자물가 | 한국은행 ECOS의 공식 통계 | 지수와 전년 동월 대비 % 구분 |
| 한국 실업률 | 한국은행 ECOS의 공식 통계 | %, 계절조정 여부 명시 |
| 미국 정책금리 목표 범위 | FRED의 연준 원자료 계열 | 하한~상한 %, 실효금리와 구분 |
| 미국 소비자물가 | FRED의 BLS 원자료 계열 | 지수와 전년 동월 대비 % 구분 |
| 미국 실업률 | FRED의 BLS 원자료 계열 | %, 계절조정 여부 명시 |
| 미국 10년 국채금리 | FRED의 연준 원자료 계열 | 금리 %, 직전 관측 대비 %p |

연동 전 각 항목의 실제 계열 ID·통계표·항목 코드·빈도·계절조정·단위·재배포 조건을 원자료와 대조하여 확정한다. 환율은 매매기준율·종가 등 채택한 정의를 화면에 명시한다. 서로 다른 정의의 수치를 같은 지표로 섞지 않는다.

한국 자료는 [ECOS Open API](https://ecos.bok.or.kr/api/), 미국 자료는 [FRED 관측값 API](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)를 우선 경로로 삼는다. ECOS의 개별 통계 코드는 실제 인증키와 응답으로 구현 단계에서 확인한다.

**표시·계산 규칙**

- 1년·3년·5년 차트와 접근 가능한 데이터 표를 함께 제공한다. 초기 수집 범위는 최근 5년이며 전년 대비 계산용 선행 구간도 확보한다.
- 관측 기준일, 원자료 발표 시점(확인 가능한 경우), 마지막 수집 시각을 구분한다. 실시간 시세라고 표시하지 않는다.
- 변화율은 직전 유효 관측값 기준이며 ‘전일 대비’라는 표현은 실제 연속 일자일 때만 사용한다.
- 금리 변화의 %p와 비율 변화의 %를 구별한다. 물가지수 전년 대비 계산에는 동일 계열의 12개월 전 값을 사용한다.
- 결측값은 빈 값으로 유지하고 0으로 바꾸지 않는다. 비교 대상이 없거나 0이면 변화율을 ‘계산 불가’로 표시한다.
- 최신 발표가 없는 월·휴일은 기존 기준일을 유지한다. 월간 지표가 한 달 동안 같은 값인 것은 수집 실패와 구분한다.
- 외부 응답 오류 시 마지막 정상 자료와 ‘갱신 지연’을 표시한다. 처음부터 자료가 없으면 ‘아직 자료가 없습니다’로 표시한다.
- 관심 지표는 최대 8개를 저장하고 마이페이지·대시보드에서 우선 노출한다. 관심 순서도 본인만 변경할 수 있다.
- 각 지표에 쉬운 해설, 단위·빈도, 공식 출처, 관련 용어·공개 글을 연결한다.

**완료 기준**

- 최신 수치뿐 아니라 차트의 과거 표본도 공식 원자료와 일치한다.
- 정책금리 범위, %와 %p, 결측·0·휴일·수정 발표를 올바르게 처리한다.
- 제공기관 장애 중에도 기존 정상 값이 손상되지 않는다.
- API 키와 제공기관의 인증 URL이 브라우저·로그에 노출되지 않는다.

### 4.5 경제 일정 캘린더

**사용 흐름**

1. 이번 주 목록 또는 월간 달력에서 경제 일정을 확인한다.
2. 국가·주제·발표 종류로 필터링한다.
3. 상세 화면에서 발표 내용, 관측 대상 기간, 공식 출처, 연결 지표·용어를 확인한다.
4. 관심 일정을 저장하고 마이페이지에서 다시 확인하거나 `.ics` 파일로 내려받는다.

**초기 일정**

- 한국: 한국은행 기준금리 결정, 소비자물가, 고용·실업, GDP 발표.
- 미국: FOMC 금리 결정, CPI, 고용보고서, GDP 발표.
- 일정은 각 기관의 공식 발표 달력을 기준으로 등록한다. FRED의 발표 날짜 API는 미국 주요 통계 일정 수집을 보조한다.
- FOMC는 [연준 공식 회의 일정](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm), 미국 CPI는 [BLS 공식 발표 일정](https://www.bls.gov/schedule/news_release/cpi.htm)을 확인한다. 한국 일정도 해당 발표기관의 원문 URL을 저장한다.

**시간·수정·결과 처리**

- 확인된 시각은 UTC 시각과 원본 IANA 시간대를 함께 저장하고 한국 시간으로 변환한다. 영어 화면도 기본 시간대는 동일하다.
- 날짜만 확인되면 별도의 현지 날짜와 `date_only` 정밀도로 저장한다. ‘시각 미정·발표기관 현지 날짜 기준’을 표시하고 임의의 자정 시각을 만들지 않는다.
- [FRED 발표 날짜 API](https://fred.stlouisfed.org/docs/api/fred/releases_dates.html)의 날짜를 정확한 발표 시각이나 FRED 값 입수 시점으로 간주하지 않는다.
- 미국 서머타임, 한국에서 다음 날로 넘어가는 일정, 월말·연말 경계를 검증한다.
- 일정 상태는 예정·발표 완료·연기·취소로 구분한다. 예정 시간이 지났다는 이유만으로 발표 완료로 변경하지 않는다.
- 기관의 안정적인 이벤트 ID를 우선 사용한다. 없으면 발표 종류와 대상 기간/회의 식별자를 조합한다. 변경 가능한 날짜 자체를 유일 식별자로 쓰지 않는다.
- 일정 날짜가 변경되어도 저장한 관심 일정은 유지된다. 상세 화면에서 변경 시각과 새 일정을 확인할 수 있다.
- 발표 결과는 해당 지표의 대상 기간과 일치하는 관측값이 수집된 후에만 표시한다. ‘발표 당시 이전 값’과 ‘현재 수정된 이전 값’을 구분하고, 최초 발표 수치를 보관하지 못했으면 이를 추정하지 않는다.
- 시장 예상치·예상 대비 서프라이즈·임의의 중요도 별점은 1차에서 제공하지 않는다.
- `.ics`는 시각이 있으면 시간 일정, 날짜만 있으면 종일 일정으로 내보낸다. 내려받은 파일은 자동 갱신되지 않음을 알려 준다.
- 자동 수집이 불안정한 공식 자료는 출처·검토일을 기록한 운영 데이터 파일로 등록한다. 파서 오류로 일정을 자동 삭제하지 않는다.

**완료 기준**

- 시간대와 날짜 정밀도에 따라 날짜·시각이 정확히 표시된다.
- 같은 일정의 재수집·연기 처리로 중복 행이 생기지 않는다.
- 일정을 저장한 회원만 자신의 저장 목록을 볼 수 있다.
- 공식 발표 지연·취소·수정과 날짜만 있는 일정이 모두 정상 표시된다.

아래는 신규 테이블의 논리 설계다. 실제 SQL과 인덱스 이름은 구현 시 기존 마이그레이션에 이어 생성한다. 모든 신규 테이블은 기존 `space_` 접두사를 따른다.

| `space_indicator_definitions` | ID, slug, 국가, 단위, 빈도, 계절조정, 한국어·영어 설명, 변환 규칙, 대표 topic_id·term_id | 활성 항목 공개 읽기, 운영 쓰기 |

| `space_sync_runs` | 제공기관, 작업 종류, 상태, 커서, 처리 건수, 실패 코드, 시작·종료일 | 내부 작업 전용 |

**관계와 무결성**

- 개인 데이터의 `user_id`는 인증 사용자와 연결하고, 계정 영구 삭제 시 함께 삭제한다.
- 북마크 폴더는 회원 ID까지 묶어 참조하여 타인의 폴더와 연결하지 못하게 한다. 폴더 삭제 시 북마크 이동과 삭제를 한 트랜잭션으로 처리한다.
- 글-주제·글-용어 연결은 기존 글의 `(id, space_id)` 복합 외래키와 소유권 검사를 사용한다.
- 신규 연결 때문에 기존 `space_posts`, 공간 주소, 글 주소, 카테고리·태그의 의미를 바꾸지 않는다.
- 용어와 주제는 사용 중인 항목을 영구 삭제하기보다 비활성화한다. 기존 참조는 유지하고 새 선택·공개 노출 규칙을 적용한다.
- 수집 결과는 동일한 키로 재실행해도 중복되지 않도록 upsert한다. 개정된 관측값은 갱신하되, 일정 결과에 표시할 최초 확인 값·이전 값은 별도 결과 이력으로 보관한다.
- 최초 확인 값은 수집 시점의 사본이다. 발표 시점 원자료와 대조하지 못한 경우 ‘최초 발표값’으로 표시하지 않는다. 결과 정정 내역은 일정 변경 이력과 함께 기록한다.
- 지표의 관련 글은 대표 공통 주제, 관련 용어는 대표 용어 ID로 연결한다. 일정은 연결 지표를 통해 같은 해설을 제공한다. 모든 연결에서 공개 상태를 다시 확인한다.

**인덱스와 조회 방식**

- 개인 목록: `(user_id, created_at DESC, id DESC)`, `(user_id, folder_id, updated_at DESC)`.
- 피드: 구독 테이블의 복합 유일 키, 주제 연결 `(topic_id, post_id)`, 공개 글의 `(space_id, published_at DESC, id DESC)` 부분 인덱스.
- 용어: slug 유일 키, 언어별 정규화 별칭 인덱스. 초기 30개 검색은 부분 문자열 검색으로 충분하며 대규모 검색 엔진을 추가하지 않는다.
- 지표: `(series_id, observation_period)` 유일 키와 기간 범위 조회 인덱스.
- 일정: 국가·확정 시각, 국가·날짜 전용 인덱스. 날짜만 있는 일정과 확정 시각을 별도로 조회·정렬한다.
- 실제 실행 계획과 대표 데이터로 병목을 확인한다. 피드의 중복 제거와 페이지네이션은 DB에서 처리한다.

## 6. 권한·개인정보·캐시 설계

기존 서버 전용 Supabase 모듈과 회원 JWT 기반 조회를 재사용한다. 브라우저가 전달한 회원 ID나 표시용 닉네임으로 권한을 결정하지 않는다.

| 데이터/행동 | 비로그인 | 로그인 회원 | 내부 운영·수집 작업 |
| --- | --- | --- | --- |
| 공개 용어·주제·지표·일정 조회 | 허용 | 허용 | 허용 |
| 공개 글 기반 피드·관련 글 | 공개 부분만 | 공개 부분만 | 목적에 맞는 범위 |
| 북마크·메모·구독·관심 설정 | 차단 | 자신의 데이터만 | 사용자용 API로 접근하지 않음 |
| 자기 글의 주제 변경 | 차단 | 글 소유자만 | 일반 회원 API와 분리 |
| 공통 용어·주제·원자료 수정 | 차단 | 차단 | 승인된 서버 작업만 |
| 수집 로그·오류·진행 커서 | 차단 | 차단 | 허용 |

- 신규 노출 테이블마다 GRANT와 RLS를 함께 정의한다. 개인 데이터의 조회·삭제는 본인 조건, 삽입·수정은 변경 전후 소유자 조건을 검증한다.
- 일반 회원 기능에 secret key로 우회하는 조회를 사용하지 않는다. 운영용 클라이언트는 수집·검수 데이터 등록에만 한정한다.
- DB 뷰·RPC도 호출자의 권한을 유지하는 방식으로 설계한다. 기존 글 소유권과 공개 조건을 생략하는 별도 피드 경로를 만들지 않는다.
- 직접 Supabase API 호출에도 동일한 접근 제한이 적용되는지 검증한다. 자세한 기준은 [Supabase RLS 공식 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)를 따른다.
- 개인 화면·API·피드는 `private, no-store`와 `noindex`를 적용한다. 메모 내용과 인증 정보는 로그·분석 이벤트에 넣지 않는다.
- 기존 `src/proxy.ts`는 전역 `no-store` 정책을 적용하고 있다. 1차에서는 이를 유지하고 외부 자료를 DB에 저장해 호출량을 줄인다. 인증 응답의 CDN 캐시를 새로 열지 않는다.
- 공개 용어·지표 데이터의 내부 캐시가 필요하면 언어·콘텐츠 버전별로만 저장한다. 개인 설정·글 공개 상태와 결합한 응답은 공유 캐시에 넣지 않는다.
- 모든 변경 요청은 기존 동일 출처 검사와 인증 검사를 적용한다. 입력 길이·UUID·정렬·기간·페이지 크기를 제한한다.
- 로그인 복귀 경로는 허용된 내부 경로만 사용한다. 북마크·구독 요청을 GET 링크만으로 실행하지 않는다.

## 7. 서버 API와 코드 구성

### 주요 API 계약

| 경로 | 기능 | 인증 |
| --- | --- | --- |
| `/api/bookmark-folders` 및 `/:id` | 폴더 목록·추가·변경·삭제 | 필수 |
| `/api/bookmarks` 및 `/:id` | 저장 글 목록·저장·메모/폴더 수정·삭제 | 필수 |
| `/api/follows/spaces/:id` | 공간 구독 PUT·해제 DELETE | 필수 |
| `/api/follows/topics/:id` | 주제 구독 PUT·해제 DELETE | 필수 |
| `/api/following` | 개인 피드와 다음 커서 | 필수 |
| `/api/glossary` | 공개 용어 검색·짧은 설명 | 불필요 |
| `/api/topics` | 공개 주제 목록 | 불필요 |
| `/api/indicators` 및 `/:slug` | 지표 정의·기간별 관측값 | 불필요 |
| `/api/indicator-favorites` | 관심 지표·순서 관리 | 필수 |
| `/api/calendar` 및 `/:id` | 필터별 일정·상세 | 불필요 |
| `/api/event-saves/:id` | 관심 일정 저장 PUT·해제 DELETE | 필수 |
| `/api/calendar/:id/ics` | 공개 일정 파일 다운로드 | 불필요 |

공개 페이지의 최초 데이터는 서버 함수로 바로 읽고, 브라우저 필터 변경·추가 로딩·저장 행동에 API를 사용한다. 모든 서버 페이지가 자기 API를 다시 HTTP 호출하는 구조는 피한다.

목록 응답은 `items`와 `nextCursor`를 사용한다. 잘못된 입력, 미인증, 권한 없음, 존재하지 않음, 수정 충돌, 과다 요청, 외부 자료 불가를 구분하되 숨겨진 데이터의 존재 여부를 오류 메시지로 노출하지 않는다. 공개·비공개 판정은 HTTP 상태와 응답 본문 모두에 적용한다.

### 추가·수정 대상

- `src/app/[locale]/(public)/`: 새 공개 화면과 개인 읽기 화면.
- `src/app/api/`: 위 기능별 API와 공통 검증.
- `src/lib/server/`: 북마크, 구독·피드, 용어, 지표, 일정 서비스.
- `src/lib/server/providers/`: FRED·ECOS의 서버 전용 어댑터.
- `src/components/`: 저장·구독 버튼, 메모 폼, 용어 설명 창, 지표 차트, 일정 목록. 반복 스타일은 기존 CSS Modules 패턴을 따른다.
- `src/components/Markdown.tsx`: 용어 연결을 추가하되 기존 HTML 정화·목차·미디어 제한을 유지한다.
- `src/components/Editor.tsx` 및 글 저장 RPC: 공통 주제 선택과 글-주제·용어 연결을 기존 버전 검사와 함께 저장한다.
- `src/lib/i18n/en.json`, 언어 라우팅·메타데이터 도우미, 사이트맵: 새 기능 번역과 URL 반영.
- `content/`: 검수한 주제·용어·지표 정의·수동 보완 일정.
- `scripts/`: 데이터 등록, 최초 수집, 검증 스크립트.
- `netlify/functions/`: 운영 배포의 예약 수집 작업.
- `supabase/migrations/`, `tests/`: 신규 스키마·RLS·수집 정규화·행동 검증.

차트는 접근 가능한 표를 함께 제공하는 소형 차트 라이브러리를 구현 단계에서 선정한다. 새 패키지는 기존 의존성으로 해결되지 않는 부분에만 추가하고 버전·라이선스·잠금 파일을 확인한다. 현재 Next.js 버전의 번들 문서를 읽고 구현한다.

## 8. 외부 자료 수집과 운영

### 수집 흐름

```text
공식 자료 → 제공기관별 어댑터 → 형식·단위 검증 → Supabase 저장
                                                      ↓
회원·방문자 ← Next.js 화면/API ← 저장된 정상 자료와 상태
```

- 방문자가 화면을 열 때마다 외부 API를 호출하지 않는다.
- 최초 5년치 수집은 재개 가능한 전용 스크립트로 나누어 실행한다. 이후 예약 작업은 변경 가능 구간만 수집한다.
- 지표는 제공기관별 매시간 갱신 시도, 일정은 6시간 간격 확인을 시작 기준으로 삼는다. 실제 호출 제한·변경 주기·비용에 맞춰 간격을 조정한다.
- 단기 수정 구간은 반복 수집하고, 월 1회 최근 5년을 분할 재검사하여 오래된 통계 개정도 반영한다. 외부 제공량에 맞춘 커서를 저장한다.
- 제공기관별 작업 잠금과 만료 시간을 두어 중복 실행을 막는다. 재시도는 제한 횟수와 지연을 적용하고 429 응답의 재시도 지시를 따른다.
- 응답 검증에 실패한 결과는 정상 자료에 덮어쓰지 않는다. 오류 로그에는 제공기관·계열 ID·상태 코드만 기록한다.
- 수동 검수 일정의 시간·설명 수정은 자동 수집이 덮어쓰지 않도록 필드별 운영 우선값을 구분한다.

예약 작업은 기존 Netlify에 둔다. [Netlify 공식 문서](https://docs.netlify.com/build/functions/scheduled-functions/)에 따르면 예약 함수는 UTC 기준이며 실행 한도가 30초이고, 운영 배포에서만 자동 실행된다. 따라서 한 번의 실행을 작은 묶음으로 나누고 20초 안에 종료하는 것을 내부 목표로 삼는다. 초기 적재나 대량 재수집을 예약 함수 한 번에 몰아넣지 않는다. 미리보기 배포에서는 수동 검증을 별도로 실행한다.

**장애 표시 기준**

- 마지막 수집 성공 시각과 지표 관측일을 별도로 저장한다.
- 정해진 수집 주기의 2배 이상 성공이 없으면 갱신 지연을 표시한다. 월간 지표의 오래된 관측일 자체를 장애로 판정하지 않는다.
- 운영자는 실패 건수·마지막 성공·처리량을 로그와 검사 스크립트로 확인한다. 브라우저에 내부 원문 오류를 노출하지 않는다.
- 외부 키가 없으면 해당 제공기관 작업만 중단하고 공개 화면에는 연결 준비 상태를 표시한다. 실제처럼 보이는 가짜 수치를 채우지 않는다.

### 환경변수와 준비 항목

| 항목 | 용도 | 연결 전 동작 |
| --- | --- | --- |
| 기존 Supabase 환경변수 | 회원 데이터·공통 자료 저장 | 현재 서버 전용 설정 재사용 |
| `FRED_API_KEY` | FRED 계열·관측값·발표 날짜 수집 | 미국 자동 수집 준비 상태 |
| `ECOS_API_KEY` | 한국 통계 수집 | 한국 자동 수집 준비 상태 |
| `ECONOMIC_SYNC_ENABLED` | 예약 수집 활성화 제어 | 기본 비활성, 검증 후 활성화 |
| 기존 `AUTH_EMAIL_READY` | 일반 가입·재설정 메일 개방 | 기존 보류 상태 유지 |
| 기존 AWS S3 환경변수 | 기존 글 첨부 기능 | 이번 5개 기능의 필수 조건 아님 |

신규 비밀값에는 `NEXT_PUBLIC_` 접두사를 사용하지 않는다. 예약 함수에서도 사용할 수 있는 환경변수 범위를 확인한다. 키·비밀번호는 문서·Git·배포 로그에 기록하지 않는다.

FRED 자료는 계열별 원 소유자의 이용 조건이 다를 수 있다. 사용할 계열별 재배포 조건과 출처 표시를 확인하고, FRED API 안내 문구·약관 링크를 제공한다. [FRED API 이용 조건](https://fred.stlouisfed.org/docs/api/terms_of_use.html)에 맞춰 지표 페이지와 서비스 이용 안내를 정리한다. API 키 발급만으로 모든 계열을 재배포할 수 있다고 간주하지 않는다.

## 9. 한국어·영어, 검색 노출, 접근성

### 한국어·영어

- 버튼·오류·상태·필터·단위 설명·날짜·숫자 형식을 양쪽 언어로 제공한다.
- 공통 주제·초기 30개 용어·지표 설명은 두 언어를 검수해 배포한다. 원자료 기관명·고유 명칭은 필요 시 병기한다.
- 글·메모·사용자 폴더명은 원문을 유지한다. 화면 언어가 달라졌다고 글의 원문 언어를 번역된 것으로 표시하지 않는다.
- 메모 수정 중 언어 전환에는 미저장 확인을 적용한다.

### 검색 노출

- 공개 용어·주제·지표·일정 상세를 서버 렌더링하고 제목·설명·canonical·언어별 대체 링크를 제공한다.
- 검수된 공개 용어와 설명이 충실한 지표·주제 페이지를 사이트맵에 추가한다. 일정은 설명이 있는 상세만 포함하고 단순 필터 URL은 제외한다.
- 개인 자료함·개인 피드·구독 관리·내 일정은 검색 제외 및 비공개 응답으로 처리한다.
- 용어에는 정의 중심 구조화 데이터, 탐색에는 BreadcrumbList를 검토한다. 구조화 데이터 적용을 검색 결과의 특별한 표시 보장으로 설명하지 않는다.
- 삭제·비공개 글을 주제·용어·일정·지표의 관련 글과 통계에서도 제외한다.
- 기존 광고 정책을 유지하고 개인 메모·개인 피드에 광고 스크립트를 넣지 않는다.

### 접근성과 반응형

- 360px·390px 모바일과 1280px 데스크톱에서 검증한다.
- 색상만으로 상승·하락·공개 여부를 표시하지 않고 텍스트·기호를 함께 사용한다.
- 차트에는 같은 내용을 읽을 수 있는 표와 요약을 제공한다.
- 달력의 모바일 기본 보기는 목록으로 제공하고, 월간 보기에서도 키보드로 날짜를 탐색할 수 있게 한다.
- 설명 창에는 열기·닫기, Escape, 초점 복귀를 지원한다. 저장 결과는 보조 기술에서도 읽을 수 있도록 알린다.

| 5. 경제 일정 | 공식 일정 등록·수집, 시간대, 저장·변경·취소·결과, ICS | 달력과 관심 일정 |
| 6. 통합 출시 | 양 언어·권한·공개 전환·장애 검증, 운영 문서, GitHub·Netlify 배포 | 검증 보고와 운영 반영 |

외부 키 준비와 공식 일정 검수는 0단계부터 시작한다. 준비가 늦어도 1~3단계와 4~5단계의 화면·어댑터·테스트 작성은 진행할 수 있다. 실제 데이터 연결과 운영 검증은 별도 완료 항목으로 기록한다.

## 11. 검증 계획

| 영역 | 필수 시나리오 |
| --- | --- |
| 북마크·메모 | 중복 저장, 폴더 삭제, 타인 폴더 연결 차단, 메모 충돌, 원문 비공개·삭제, 계정 정리 |
| 용어 사전 | 한·영 검색·약어, 중복 별칭, 링크/코드 제외, 정화 유지, 키보드·모바일 설명 창 |
| 구독·피드 | 공간/주제 각각 일치, 중복 일치, 구독 해제, 커서 페이지, 수정 글 순서, 비공개 배제 |
| 지표 | 공식 값 대조, 계열·단위·계절조정, %p/%, 결측·0, 범위 지표, 개정값·지연 응답 |
| 일정 | 미국 서머타임 전환, 날짜 경계, 시각 미정, 연기·취소, 중복 수집, 대상 기간별 결과, ICS |
| 권한 | 익명·회원 A·회원 B, 직접 DB API, 변조된 user_id/space_id, 운영 테이블 쓰기 차단 |
| i18n·SEO | 한국어·영어 URL, 필터 유지, 미저장 전환, canonical·사이트맵, 개인 화면 noindex |
| 회귀 | 기존 로그인·마이페이지·글 CRUD·공개 전환·검색·RSS·파일 접근 정책 |
| 운영 | 인증키 없음, API 429/5xx/잘못된 응답, 작업 중단·재개, 중복 실행, 정상 자료 보존 |

검증은 다음 순서로 수행한다.

1. 타입 검사, 기능별 단위 테스트, 현재 프로젝트 테스트, 프로덕션 빌드.
2. 기존 PostgreSQL 호환 테스트 환경에서 신규 마이그레이션·제약·RLS 검증.
3. 실제 Supabase의 임시 회원 두 개로 API·DB 접근 격리 및 CRUD 확인. 로컬 DB 테스트만으로 운영 검증을 대체하지 않는다.
4. 한국어·영어, 모바일·데스크톱 브라우저에서 실제 행동 확인.
5. 공식 데이터의 최근 값·과거 표본·일정 시각을 직접 대조하고 예약 수집의 운영 실행 결과 확인.
6. 검사에 사용한 계정·글·개인 설정을 정리하고 결과를 문서로 보관.

성능은 초기 관측치 약 5만 건, 테스트용 공개 글 1만 건을 기준으로 대표 목록·피드 조회를 측정한다. DB 조회 500ms 이내를 초기 점검 목표로 두고, 초과 시 실행 계획과 인덱스를 조정한다. 이 수치는 운영 응답시간 보장이 아닌 검증 목표다.

## 12. 배포·변경 관리

- 신규 테이블·선택적 연결을 먼저 추가하여 기존 배포와 호환되게 한다. 기존 데이터 삭제나 초기 마이그레이션 재실행은 하지 않는다.
- DB 변경 전 현재 상태와 복구 수단을 확인하고, 마이그레이션과 RLS를 함께 검증한다.
- 개인화·사전·데이터 기능별 활성화 설정을 두어 검증된 기능부터 공개한다. 예약 수집 활성화는 화면 공개와 분리한다.
- 공통 데이터 등록 후 실제 Supabase 검증을 수행하고, GitHub `master` 변경을 기존 Netlify 자동 배포에 연결한다.
- 운영 도메인에서 로그인, 개인 자료 격리, 공개 상세 SEO, 실제 자료, 예약 작업을 확인한다.
- 문제 발생 시 해당 기능/수집을 비활성화하거나 이전 앱 배포로 복귀한다. 추가 테이블과 개인 메모는 보존하고, 데이터를 지우는 롤백 SQL을 기본 복구 방식으로 쓰지 않는다.
- 문서에는 연결 완료·미완료 항목을 구분한다. API 키, 인증 메일, 이용 조건 확인이 끝나지 않은 기능은 실제 연동 완료로 보고하지 않는다.

## 15. 참고 자료와 확인 범위

설계 기준으로 현재 저장소의 `README.md`, `package.json`, `netlify.toml`, 회원 공간 마이그레이션, `src/lib/server/`, Markdown 렌더러, 언어 라우팅, 사이트맵과 프록시 코드를 확인했다. 외부 서비스 계정 상태·요금·키 보유 여부는 이번 문서 작성에서 변경하거나 재검증하지 않았다.

아래 공식 문서는 2026-10-16에 확인했다. 실제 구현 전 API·배포 제한의 변경 여부를 다시 확인한다.

- [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security): 데이터 접근 정책 설계.
- [ECOS Open API](https://ecos.bok.or.kr/api/): 한국 통계 연동의 공식 진입점. 개별 코드·한도는 구현 전 확인.
- [FRED 관측값 API](https://fred.stlouisfed.org/docs/api/fred/series_observations.html): 미국 통계 관측값 수집.
- [FRED 발표 날짜 API](https://fred.stlouisfed.org/docs/api/fred/releases_dates.html): 발표 날짜와 데이터 입수 시점의 구분.
- [FRED API 이용 조건](https://fred.stlouisfed.org/docs/api/terms_of_use.html): 계열별 이용 제한·출처·서비스 안내.
- [연준 회의 일정](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm), [BLS CPI 일정](https://www.bls.gov/schedule/news_release/cpi.htm): 미국 공식 일정 확인.
- [한국은행 경제금융용어 자료](https://www.bok.or.kr/portal/bbs/B0000249/view.do?menuNo=200765&nttId=235017): 용어 사실 확인과 출처.
- [Netlify 예약 함수](https://docs.netlify.com/build/functions/scheduled-functions/): 시간대·실행 한도·운영 배포 동작.
