## 자동 검증의 핵심 사례

- 북마크 소유권, 타인 폴더 연결 거절, 폴더 최대 50개, 메모 버전 충돌, 원문 비공개 이후 메모만 유지, 폴더 삭제 후 분류 없음.
- 글 저장과 공통 주제 저장의 트랜잭션, 최대 3개 주제, 구독 이유 중복 제거, 26개 글의 커서 목록·중복 방지, 구독 해제.
- 관심 지표·일정의 회원 간 격리, 일반 회원의 원자료 쓰기 거절, 미승인 계열 관측값 차단, 내부 수집 작업 잠금 중복 차단.
- 한국어·영어 30개 용어와 별칭/관련 용어 참조, 본문 첫 등장 연결, 기존 링크·코드·제목 제외, 악성 HTML/URL 정화.
- 결측/0/전년동월/%p/금리 상·하한, 제공기관 형식/단위/계열 불일치, 429 Retry-After, 잘린 응답, 시간 예산, 6년 분할 수집 커서.
- KST 날짜 경계, 미국 서머타임 전환, 날짜만 있는 일정, ICS UTF-8 줄 접기와 삽입 방지, 변경된 일정의 ID/이력 유지, 수동 검수 우선.
- 양 언어 SSR·canonical·개인 페이지 로그인 차단·no-store, 필터 noindex, ICS 영어 다운로드, 외부 복귀 URL 차단, 공개 사이트맵의 개인 경로 제외.

## 아직 확인하지 못한 흐름

- 실제 로그인 회원이 브라우저에서 메모를 저장하고 새로고침하는 전 과정. `scripts/economy-live-check.mjs`와 운영 절차에 준비했다.
- 실제 FRED/ECOS 키로 수집한 수치·갱신 상태와 공식 값 대조.
- 실제 수집 데이터의 그래프 브라우저 표시, 운영 서버의 성능·Supabase Advisors 결과.
- 실제 메모 편집 중 언어 전환/이탈 확인과 용어 팝업의 키보드 초점 복귀. 코드에 처리되어 있으나 로그인된 실데이터 화면의 브라우저 검증은 남았다.

위 보류 항목을 로컬 테스트 통과로 대신 완료 처리하지 않았다. 상세 적용 순서는 [운영 메모](economy-operations.md)를 따른다.
